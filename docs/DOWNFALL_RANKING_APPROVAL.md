# 멸망전 TOP 10

현재 상태: VERIFIED LOCALLY. 운영 DB 적용, 환경변수 변경, 커밋·푸시·배포는 아직 하지 않았습니다. 운영 반영은 승인과 아래 미완료 릴리스 검증을 거쳐야 합니다.

## 이용 흐름

- 시작 화면과 엔딩에서 TOP 10을 열어 봅니다. 다른 이용자와 공유하는 서버 랭킹이며, 기록이 없으면 빈 목록으로 표시합니다.
- 기존 일반 플레이는 그대로입니다. **랭킹 도전**으로 새로 시작한 게임만 등록할 수 있습니다. 이미 끝난 로컬 점수를 소급 등록하지 않습니다.
- 체력이 소진되는 순간 점수가 확정됩니다. 은혜 연출로 사라지는 적은 점수에 포함하지 않습니다. 말씀 엔딩도 유지합니다.
- 등록은 선택입니다. 영문 이니셜 3자를 입력하고, 이니셜과 점수의 공개에 동의한 뒤 제출합니다. 동의 체크는 매번 꺼진 상태로 시작합니다.
- 같은 이니셜의 여러 기록이 있을 수 있습니다. 계정이나 사용자별 순위가 아니라 **기록 TOP 10**입니다. 점수는 신앙 수준을 뜻하지 않습니다.
- 점수 내림차순으로 최대 10개를 보여 줍니다. 동점은 같은 순위(1, 1, 3)를 받으며, 먼저 등록한 기록이 앞에 남습니다. 0점은 공개 등록하지 않습니다.
- 랭킹 기록은 최대 30분의 실제 플레이 입력을 받습니다. 입력량 한도에 먼저 도달하는 경우도 있습니다. 한도를 넘으면 해당 플레이의 랭킹 등록은 중단하지만 게임은 계속할 수 있습니다. 일반 플레이에는 이 랭킹 제한이 없습니다.
- 일시정지와 화면 전환은 플레이를 멈출 뿐 자동 실격 처리하지 않습니다. 서버에서 실제 경과 시간보다 빠른 기록은 거릅니다.

## 점수 검증과 한계

서버가 정해진 시드와 60Hz 규칙으로 이동, 조준, 발사, 회피, 다음 공세 입력을 다시 실행합니다. 브라우저가 보내는 점수 숫자는 받지 않습니다. 체력 소진까지 도달한 기록에서 서버가 직접 점수를 계산합니다.

이는 입력 기록의 일관성을 검증하는 장치입니다. 사람이 직접 했는지, 봇이나 수정된 클라이언트를 쓰지 않았는지까지 보증하지 않습니다. 기기별 재미·조작감·프레임 성능도 별도의 실제 기기 확인이 필요합니다.

## 저장·공개 범위

공개 API는 순위, 이니셜 3자, 점수만 반환합니다. 로그인, 이메일, 실명, 카메라, 마이크는 사용하지 않습니다. 전체 플레이 입력은 저장하지 않고 검증에만 사용합니다.

임시 시도 기록은 생성/만료 시각, 검증 결과, 입력 해시, 동의 버전, 중복 제출 확인값을 보관합니다. 시도는 2시간 후 만료되며, 요청이 들어올 때 제한된 개수씩 만료 데이터를 정리합니다. 방문이 끊기면 물리 삭제도 다음 요청까지 기다립니다. 시도 기록 최대 2,048개, 네트워크별 미완료 시도 최대 4개입니다.

요청 제한은 Vercel이 전달한 접속 IP를 일별 HMAC으로 변환해 적용하며 원본 IP를 별도로 저장하지 않습니다. 같은 네트워크 이용자는 제한을 공유합니다. 네트워크나 날짜가 바뀌면 진행하던 랭킹 시도의 확인이 실패할 수 있습니다. 공개 기록은 더 높은 기록에 밀리거나 운영자가 삭제할 때까지 남습니다. 계정이 없어 본인 확인을 통한 자동 삭제 기능은 제공하지 않습니다.

## 승인 대상 변경

1. 기존 전용 Supabase 프로젝트에 `downfall_challenge` 스키마와 세 테이블, 서버 전용 `public.downfall_challenge_rpc` 함수를 추가합니다.
2. 기존 `service_role`에 새 객체만 접근 허용합니다. 모든 새 테이블에 RLS를 켜고 `anon`, `authenticated`, `PUBLIC`의 접근을 차단합니다. 기존 랭킹·그일라·시편 데이터와 함수는 변경하지 않습니다.
3. `/api/downfall-challenge/{record,attempts,finish,submit,invalidate}` 다섯 경로를 추가합니다. 점수 제출은 같은 운영 사이트에서만 가능합니다.
4. 기존 서버 비밀키와 프로젝트/허용 출처 설정을 재사용합니다. 신규 `DOWNFALL_ONLINE_ENABLED`는 기본 꺼짐입니다. 새 유료 서비스나 계정은 만들지 않습니다.
5. 검증한 코드와 마이그레이션을 승인한 후 배포하고 새 플래그를 켭니다. 운영 서버에는 가짜 랭킹 기록을 넣지 않습니다.

마이그레이션 파일: `supabase/migrations/20261006213000_downfall_top10.sql`.

## 검증과 롤백

프로토콜 단위 테스트, 실제 로컬 PostgreSQL(PGlite) 권한·동의·중복·동점·정렬 테스트, 같은 HTTP API를 사용하는 브라우저 테스트를 수행합니다. 모든 테스트 점수는 폐기 가능한 로컬 DB에만 남습니다. 실제 운영 PostgREST 설정과 전송 검증은 승인된 적용 후 별도로 확인해야 합니다.

문제가 생기면 새 플래그를 끄고 승인된 이전 코드로 되돌립니다. DB 기록은 삭제 승인을 받기 전까지 보존합니다. 기존 게임의 랭킹이나 스키마를 삭제하거나 되돌리지 않습니다.
