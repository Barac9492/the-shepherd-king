# 그일라 2인 구출전: 로컬 시제품 구조

기준 배포: `025cdaa911f9d46a747d4d286d5dc45950051f5d` (스토리·챌린지·산책 메뉴, PR #19).
독립 체크아웃과 `codex/keilah-coop-prototype` 브랜치에서 작업한다. 기존 작업 폴더, 개인 게임 판정기, 운영 API 및 DB를 수정하지 않는다.

## 선택한 최소 구조

기존 프로젝트는 정적 브라우저 게임 + Vercel 개인 랭킹 API + Supabase 검산/기록 구조다. 실시간 방 서버나 플레이어 인증은 없다. 개인 게임의 결과 제출 API를 협동 상태 동기화 용도로 재사용하지 않는다.

이 시제품은 **하나의 지속 실행 Node 프로세스**가 별도 `/api/keilah/*` HTTP API와 정적 파일을 제공한다. 350ms 간격으로 독립 브라우저들이 같은 서버 상태를 가져온다. 게임은 노드 간 이동/가족 인솔 방식으로, 위치·진행·시계·구출·통로·완주·TOP 10을 서버만 판정한다. 클라이언트는 이동 목적지와 동작만 보낸다. 실시간 액션의 프레임 정밀도를 요구하지 않는 작은 지도로 범위를 제한했다.

- 8자리 무작위 초대 코드와 최대 2개의 자리. 자리는 무작위 256비트 bearer capability로 인증하며 토큰은 URL/공개 스냅샷에 포함하지 않는다.
- 토큰은 해당 탭의 sessionStorage, 서버에는 해시로 보관한다. 같은 탭의 새로고침으로 자리를 복구하며 새 탭이나 다른 기기로 토큰을 이전하는 기능은 없다.
- create/join은 요청 UUID로 2분간 중복 제거, 동작은 자리별 증가 sequence와 run 번호로 중복/이전 판 재전송을 방어한다.
- 클라이언트가 score, time, position, rescue 수를 제출하는 API는 없다. 임의 필드와 비인접 이동을 거부한다.
- 고정 지도/규칙, 서버 monotonic clock, 완주 기록 0.1초 단위. 두 사람 모두 통로 확보 + 최소 1팀 구출 + 전원의 남문 도착 + 두 사람의 탈출이 조건이다. 처음 건너는 동안 동료의 손잡이가 필요하고, 한 번 확보한 통로는 열린 상태를 유지한다. 이후 양쪽으로 갈라져 가족을 한 팀씩 남문으로 인솔할 수 있다.
- 8초 이상 heartbeat가 없으면 동작 정지/순위 제외, 60초 이내 복구하면 연습 재개. 벽시계는 계속 흐른다. 서버 처리 간격 2초 초과도 순위 제외한다.
- 방 나가기는 진행 중 판을 종료하고 토큰을 폐기한다. 남은 동료는 재도전 대기실에서 새 동료를 받을 수 있다.
- 방은 마지막 인증 접근 후 30분에 만료. 동시 방 100개, 중복 수신 캐시 500개, 판 10분, IP당 분당 요청 1,800개, JSON 2KiB, 요청 body 5초 제한.
- 로컬 서버의 같은 origin만 POST 허용. GET 상태도 자리 토큰 필요. 기록 조회만 공개한다.
- 개인 이름/채팅/음성/카메라/새 오디오 에셋 없음. 팀 코드는 해당 서버의 메모리 TOP 10에만 남는다.

## 운영 배포 전에 필요한 별도 작업

**현재 상태로 Vercel에 push/deploy하면 안 된다.** 메모리 방을 Vercel의 여러 독립 Function 인스턴스에 분산하면 같은 방 상태가 달라지므로, 이 구현에는 Vercel API adapter를 만들지 않았다.

운영에는 다음 중 한 구조가 필요하다.

1. 지속 실행 협동 서버와 HTTPS 역방향 프록시, 공유 영속 저장소/단일 방 소유권, 장애 복구 및 전체 노드 간 rate-limit을 준비한다.
2. 또는 기존 Supabase에 격리된 협동 테이블/RPC와 원자적 명령 처리를 설계하고 서버 권한으로 검산·갱신하는 구조로 이식한다. 그 경우에만 새 migration, RLS/권한 검증 및 동시성 DB 테스트를 준비한다.

이번 로컬 선택에는 새 credential, Supabase 권한, DB migration이 필요하지 않다. 운영 DB/비밀키를 읽거나 쓰지 않았다. 운영 호스팅, 영속 저장소 및 인증의 선택과 적용은 별도 승인 대상이며 이 프로토타입은 운영 준비 완료로 표시하지 않는다.

## 공정성 한계

동일 프로세스의 서버 판정으로 점수/시간 직접 조작은 차단한다. 하지만 실제 두 사람인지, 한 사람이 두 클라이언트를 조작하는지 또는 자동화인지 판별하지 않는다. 네트워크 지연과 350ms 폴링으로 입력/표시에 차이가 있고 0.1초 단위 표시는 기기 간 정밀 공정성을 보증하지 않는다. bearer token을 가진 탭은 같은 자리를 조작할 수 있으므로 운영에는 세션 소유권/인증 정책도 더 필요하다.

## 성경과 창작 범위

공식 대한성서공회 사무엘상 23:1–13의 그일라 구출과 철수 본문을 확인했다:
https://www.bskorea.or.kr/bible/korbibReadpage.php?version=GAE&book=1sa&chap=23

본문 전체나 현대 역본 문장을 게임에 복제하지 않는다. 손잡이, 네 가족, 분기 지도, 두 플레이어, 시간 경쟁은 게임용 창작으로 명시한다. 결말은 모두 성 밖으로 안전하게 떠나는 것이며 사울을 처치하는 결말은 없다.
